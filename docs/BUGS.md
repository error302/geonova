## 🟠 High

### H-001: `--accent` CSS variable conflict — buttons render transparent ✅ FIXED & VERIFIED
- **Where:** All pages. Verified on `/tools/leveling` Method toggle (active "Rise & Fall" becomes invisible), `/tools/curves` tab strip, `.btn-primary` CTAs.
- **Symptom:** `background: var(--accent)` resolves to `rgba(0,0,0,0)` (transparent). Selected buttons, primary CTAs, accent text all invisible or wrong-color.
- **Root cause:** `globals.css:115` declares `--accent: 22 60% 56%` (bare HSL components) which is the LAST definition in `:root`. The downstream CSS uses `background: var(--accent)` directly without `hsl()` wrapping, so the value fails to parse → falls back to transparent.
- **Fix:** Changed lines 103–127 to hex equivalents. Verified live: active tab now renders `rgb(209,123,71)` (brand orange) instead of transparent.

### H-002: Login fails with "Incorrect email or password" first try
- **Where:** `/login`
- **Symptom:** Initial DB had no admin. Seed script writes user but local dev couldn't reach Postgres from Node. Worked when seeded directly via `node -e docker exec`. For production deploy must run `seed-admin` step.
- **Fix:** Document and run seed in production.

### H-003: Fieldbook infinite loop crashes browser (ERR_INSUFFICIENT_RESOURCES) ✅ FIXED & VERIFIED
- **Where:** `/fieldbook`
- **Symptom:** `createClient()` called on every render → `dbClient` is a new object ref each render → `useEffect([dbClient])` re-fires forever → 100s of `/api/db` + `/api/auth/session` 429/ERR_INSUFFICIENT_RESOURCES → browser freezes.
- **Root cause:** `fieldbook/page.tsx` — `const dbClient = createClient()` outside memo.
- **Fix:** `useMemo(() => createClient(), [])`. Verified live: 0 console errors after 3+ seconds (previously froze the browser).

### H-004: Admin dashboard 500 error — missing `beacons` table ✅ FIXED & VERIFIED
- **Where:** `/admin` page → `/api/admin/dashboard`
- **Symptom:** GET `/api/admin/dashboard` returns 500. `relation "beacons" does not exist`. Dashboard shows "Failed to Load Dashboard — Internal server error" placeholder.
- **Root cause:** `src/app/api/admin/dashboard/route.ts:51` queries `FROM beacons`. The schema uses `public_beacons` + `rim_beacons` (per `migrations/000_canonical_schema.sql:472` and `migrations/035_consolidated_missing_tables.sql:408`). No `beacons` table exists.
- **Fix:** Replaced single-table query with `(SELECT COUNT(*) FROM public_beacons) + (SELECT COUNT(*) FROM rim_beacons)`. Verified live: dashboard loads with 0 console errors.

### H-010: `/api/submission/preview` 500 for users without surveyor profile ✅ FIXED & VERIFIED
- **Where:** `src/lib/submission/surveyorProfile.ts` + `src/app/api/submission/preview/route.ts` + `src/lib/submission/assembleSubmission.ts`.
- **Symptom:** Users without a `surveyor_profiles` row get 500 errors on submission preview/assemble. Console error: `Surveyor profile not found for user 5a278317...`.
- **Root cause:** `getActiveSurveyorProfile()` threw on missing profile (instead of returning null). The route caught the exception and returned 500. Callers like `assembleSubmission.ts` accessed `surveyor.registrationNumber` directly without checking — TypeScript signature said it was non-null.
- **Fix:** (1) Changed `getActiveSurveyorProfile()` return type to `Promise<SurveyorProfileSubmission | null>` and return null instead of throwing. (2) Updated `preview/route.ts` to return 404 with `code: 'PROFILE_REQUIRED'` message. (3) Added null-guard in `assembleSubmission.ts:50` that throws an actionable error. Verified live: 404 (was 500) with helpful message.

### H-009: `/api/scheme/traverse/summary` 500 — `column pt.is_closed does not exist` ✅ FIXED & VERIFIED
- **Where:** `/api/scheme/traverse/summary/route.ts` lines 25-48.
- **Symptom:** 500 error on project scheme pages. Console: `Failed to load resource: 500` for `/api/scheme/traverse/summary?project_id=...`. Server log: `error: column pt.is_closed does not exist`.
- **Root cause:** Query referenced 8 columns (`is_closed, perimeter, total_perimeter, linear_error, precision_ratio, accuracy_order, computed_area_ha, computed_at`) on `parcel_traverses` table that don't exist. Schema actually stores computation results in `traverse_results.results` jsonb.
- **Fix:** Rewrote query to read from `traverse_results` (where the data actually lives), unwrapping values from the `results` jsonb column. Wrapped in try/catch for safety. Verified live: scheme page loads with 0 console errors.

### H-008: /cpd crashes — `Cannot read properties of undefined (reading 'technical')` ✅ FIXED & VERIFIED
- **Where:** `src/app/cpd/page.tsx` lines 157, 166, 175, 184.
- **Symptom:** Page renders but throws on first render — error caught by Next.js error boundary, blocks the category breakdown section.
- **Root cause:** Page builds `summary` locally with shape `{totalHours, requirementHours, compliancePercentage, status}` (lines 56-61) — does NOT include `categoryBreakdown`. But template tries to read `summary.categoryBreakdown.technical`, etc.
- **Fix:** Replaced 4 hardcoded rows with a typed map loop using optional chaining `summary.categoryBreakdown?.[cat] ?? 0`. Shows graceful fallback message when category breakdown unavailable.

### H-007: Multiple pages trigger /api/db 429 flood (infinite loop) ✅ FIXED & VERIFIED
- **Where:** `/beacons`, `/process`, `/account/billing`, `/field`, `TraverseModal`, `DynamicFieldBook`, `survey-report-builder`. Pattern present in many other files too (32 occurrences found across codebase).
- **Symptom:** Pages flood `/api/db` with requests — 184 errors logged on `/beacons` load. Server returns 429 (Too Many Requests) after rate limit kicks in.
- **Root cause:** `const dbClient = createClient()` at component body scope creates a new object reference on every render. When `dbClient` appears in any `useEffect`/`useCallback`/`useMemo` dep array (`[dbClient]`, `[..., dbClient, ...]`), the effect re-runs every render → infinite fetch loop → rate-limited.
- **Fix:** All 7 high-risk files converted to `useMemo(() => createClient(), [])`. Verified live: 0 console errors after 5 seconds on `/beacons`, `/process`, `/account/billing`.
- **Files fixed:** `src/app/beacons/page.tsx`, `src/app/beacons/submit/page.tsx`, `src/app/process/page.tsx`, `src/app/account/billing/page.tsx`, `src/app/field/page.tsx`, `src/app/tools/survey-report-builder/page.tsx`, `src/components/TraverseModal.tsx`, `src/components/workspace/DynamicFieldBook.tsx`.
- **Note:** Many other files contain the same `const dbClient = createClient()` pattern but use `dbClient` only inside event handlers (not in deps arrays) — no loop risk today, but would be best-practice to useMemo them too. Not yet swept.

### H-006: Map page OSM Buildings layer init crash ✅ FIXED & VERIFIED
- **Where:** `/map` page → `OsmBuildingsLayer.tsx` + call site in `MapClient.tsx:1536`.
- **Symptom:** `TypeError: Cannot read properties of undefined (reading 'source')` — followed by `r.addLayer is not a function` after partial fix.
- **Root cause:** Component used legacy `window.ol.*` global (no CDN loaded it). Then passed the `MutableRefObject` itself (`map={mapInstance}`) instead of `mapInstance.current`.
- **Fix:** (1) Replaced `(window as any).ol.*` with dynamic `await import('ol/source/Vector')` etc. matching the rest of the map codebase. (2) Changed call site to `map={mapInstance.current}`. Verified live: 0 console errors after 5 seconds on `/map`.

### M-007: Fieldbook precision shows `1:0` when no observations ✅ FIXED & VERIFIED

- **Fix:** Added `ratio > 0 && Number.isFinite(ratio)` guard in `realTimeQC.ts:488`. Verified live: now shows `—`.
