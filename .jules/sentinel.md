## 2025-02-23 - DOMPurify SVG Configuration and XSS in Dynamic SVGs
**Vulnerability:** XSS risk via dynamically generated SVGs (`output.svg` in `DeedPlanGenerator.tsx` and `svgOutput` in `MutationPlanGenerator.tsx`) inserted using `dangerouslySetInnerHTML` without proper sanitization. Additionally, manual configuration of DOMPurify `ALLOWED_TAGS` and `ALLOWED_ATTR` was incomplete for complex SVGs, risking functional regressions while failing to adequately protect against malicious inputs.
**Learning:** `dangerouslySetInnerHTML` requires strict sanitization of all dynamic inputs, including seemingly benign outputs like generated SVGs which can still contain malicious `<script>` tags or inline event handlers if inputs are not properly escaped. When configuring DOMPurify to allow SVGs, it's safer and more comprehensive to use `USE_PROFILES: { html: true, svg: true }` rather than attempting to manually whitelist every potential safe tag and attribute (like `cx`, `cy`, `viewBox`, etc.). Conversely, applying sanitization to trusted static data (like hardcoded beacon symbols) adds unnecessary overhead and potential SSR/hydration issues without providing real security benefits.
**Prevention:** Always wrap dynamically generated HTML/SVG in `sanitizeHtml` before passing it to `dangerouslySetInnerHTML`. Use `USE_PROFILES` for DOMPurify configuration to ensure complete support for standard HTML and SVG features while stripping dangerous ones. Avoid applying `sanitizeHtml` to trusted, statically defined assets to optimize performance and prevent hydration errors.
