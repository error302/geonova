## 2026-08-16 - [DOMPurify configuration stripping essential SVG attributes and unescaped SVG rendering]
**Vulnerability:** DOMPurify was configured manually with `ALLOWED_TAGS` and `ALLOWED_ATTR`, which stripped out essential SVG attributes (like `x1`, `y1`, `points`, `text-anchor`) causing functional regressions when rendering SVGs. At the same time, dynamically generated SVGs (e.g. from user inputs or backend generation in MutationPlan and DeedPlan) were rendered directly via `dangerouslySetInnerHTML` without sanitization, posing a stored XSS risk. Finally, trusted static enums (e.g. beacon symbols) were unnecessarily sanitized, introducing React hydration/SSR errors and performance overhead.
**Learning:** DOMPurify provides built-in profiles like `USE_PROFILES: { html: true, svg: true }` which securely and robustly allow necessary SVG attributes without opening up XSS vectors, rather than manually maintaining an incomplete allowlist. Additionally, we must distinguish between untrusted dynamic content (requires sanitization) and trusted static components (no sanitization needed to prevent hydration errors).
**Prevention:** Always use `USE_PROFILES: { html: true, svg: true }` when configuring DOMPurify to sanitize SVGs. Apply `sanitizeHtml` only to dynamically generated or untrusted HTML/SVG content before passing to `dangerouslySetInnerHTML`. Never apply `sanitizeHtml` to static, trusted components/enums.
