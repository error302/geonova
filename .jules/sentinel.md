## 2024-05-18 - [HIGH] Fix XSS vulnerabilities in SVG rendering
**Vulnerability:** Found multiple instances where unescaped user-inputted strings inside SVG output strings were rendered via `dangerouslySetInnerHTML={{ __html: output.svg }}` in `src/components/deedplan/DeedPlanGenerator.tsx` and `src/components/mutationplan/MutationPlanGenerator.tsx`. Although the codebase had a custom XML escaper (`escapeXml`), it wasn't consistently applied to all variables, leaving vectors for stored XSS via SVG payloads.
**Learning:** DOMPurify natively supports sanitizing SVG files safely, but you must configure it with `{ USE_PROFILES: { html: true, svg: true } }` rather than attempting to hand-code `ALLOWED_TAGS` and `ALLOWED_ATTR`. The manual allowlist was both incomplete (causing rendering issues) and risky.
**Prevention:** Always wrap dynamically generated SVG or HTML rendered via `dangerouslySetInnerHTML` with `sanitizeHtml`. Ensure `sanitizeHtml` is configured with `USE_PROFILES: { html: true, svg: true }` to securely support SVG syntax.
