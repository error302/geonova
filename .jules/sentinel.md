
## 2024-08-24 - DOMPurify Configuration and Trusted Enums
**Vulnerability:** The `sanitizeHtml` wrapper used DOMPurify with manually specified `ALLOWED_TAGS` and `ALLOWED_ATTR`, which failed to appropriately allow SVG sizing and positioning attributes (like `cx`, `cy`, `r`, etc). This led to potential functional regressions when sanitizing dynamically generated SVGs, or tempted developers to bypass sanitization altogether. Furthermore, applying `sanitizeHtml` to statically trusted enums (like beacon symbols) provided zero security benefit but introduced React hydration errors and SSR bugs.
**Learning:** DOMPurify's built-in `USE_PROFILES: { html: true, svg: true }` is both safer and more robust than manually maintaining allowlists for complex elements like SVGs. Also, statically generated/trusted content should bypass sanitization to avoid hydration issues, provided the input strictly conforms to an enum/constant and cannot be user-influenced.
**Prevention:** Always configure DOMPurify with profiles (e.g. `USE_PROFILES: { html: true, svg: true }`) rather than ad-hoc allowlists when dealing with SVG content. Only apply sanitization to user-generated or external untrusted inputs, avoiding it for trusted constants to prevent UI state bugs.
