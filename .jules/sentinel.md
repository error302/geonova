## 2024-05-18 - [Stored XSS] Unsanitized SVG rendering with dangerouslySetInnerHTML
**Vulnerability:** Found `dangerouslySetInnerHTML={{ __html: output.svg }}` and `dangerouslySetInnerHTML={{ __html: svgOutput }}` rendering server/client generated SVGs that could contain malicious payloads if user input is not properly escaped in the SVG generation. This represents a stored XSS vulnerability since these SVGs are generated dynamically and saved.
**Learning:** Even though we use `escapeXml` during SVG generation in the renderer, it's defense-in-depth to also run the resulting SVG string through `DOMPurify` before injecting it into the DOM via `dangerouslySetInnerHTML`. We found that our DOMPurify configuration (`sanitizeHtml`) was previously stripping valid SVG tags.
**Prevention:** Always use `sanitizeHtml` as a wrapper around any `dangerouslySetInnerHTML` call. Ensure DOMPurify allows necessary SVG tags (`path`, `g`, `polygon`, `circle`, `line`, `polyline`, `rect`, `text`, `tspan`, `defs`, `pattern`, `clipPath`) and attributes so that SVGs render correctly while stripping any `<script>` tags or malicious event handlers.
