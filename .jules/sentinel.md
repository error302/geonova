## 2024-08-28 - Stored XSS via DOMPurify SVG Configuration and Hydration Errors
**Vulnerability:** DOMPurify was stripping SVG attributes (like `cx`, `cy`, `r`, `xmlns`) and elements necessary for survey plotting because `ALLOWED_TAGS` and `ALLOWED_ATTR` were manually defined but incomplete. If untrusted SVGs were allowed without proper sanitization, it could lead to stored XSS via `dangerouslySetInnerHTML`. However, wrapping trusted static enums (like beacon symbols) with `sanitizeHtml` was causing React hydration errors.
**Learning:** Using `USE_PROFILES: { html: true, svg: true }` in DOMPurify is far safer and more robust than manually maintaining `ALLOWED_TAGS` and `ALLOWED_ATTR` for SVGs. Additionally, `sanitizeHtml` provides no security benefit for server-rendered static data (like hardcoded SVG strings for beacon symbols) and actively causes SSR/hydration bugs.
**Prevention:** Always use `USE_PROFILES` for comprehensive and safe DOMPurify configuration when both HTML and SVG are expected. Never apply `sanitizeHtml` to trusted, statically generated content or enums, as it breaks hydration and adds unnecessary overhead.
