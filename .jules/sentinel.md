## 2026-08-04 - Stored XSS Risk in Dynamically Generated SVGs Rendered via dangerouslySetInnerHTML
**Vulnerability:** Mutation plans and Deed plans dynamically generate SVG strings containing unsanitized user-provided project data. These SVGs were then directly passed to `dangerouslySetInnerHTML={{ __html: output.svg }}` in React without prior DOMPurify sanitization.
**Learning:** Even within SVG `viewBox` outputs, injected `<script>` tags or inline `onload` handlers within the SVG payload can execute JS in the user's browser (Stored XSS). Furthermore, manual `ALLOWED_TAGS` arrays in DOMPurify break SVGs because attributes like `cx`, `cy`, and tags like `g`, `polygon`, `text`, etc., often get stripped if the allowed list isn't comprehensively maintained.
**Prevention:** Always wrap dynamically generated or untrusted SVG output with `sanitizeHtml()` before using `dangerouslySetInnerHTML`. Configure DOMPurify using `USE_PROFILES: { html: true, svg: true }` instead of maintaining manual allow-lists to ensure correct functionality without sacrificing security.
