## 2024-05-24 - Stored/Reflected XSS via Dynamically Generated SVG
**Vulnerability:** The survey plan generators (`DeedPlanGenerator` and `MutationPlanGenerator`) directly injected dynamically constructed SVG strings into the DOM via `dangerouslySetInnerHTML={{ __html: output.svg }}` and `document.write(svgOutput)` without final sanitization. While the lower-level SVG renderers correctly applied XML escaping (`escapeXml`) to known user text fields to prevent basic injection, this defense was incomplete. If any vector bypassed the initial XML escaping, or if complex nested elements generated unexpected tags, a malicious surveyor could embed `<script>`, `<foreignObject>`, or `onload` handlers into the SVG. Since SVG is valid HTML context and executed when rendered inline, this created a vector for Stored XSS (when other users view the generated plans) or Reflected XSS (when printing to a new tab).
**Learning:** XML escaping alone is insufficient for generating secure SVGs intended for inline browser rendering, as it primarily protects text nodes and attributes but doesn't strip maliciously structured or unexpected nodes entirely if the generation logic has any flaw or oversight.
**Prevention:** Always pass dynamically generated HTML or SVG through DOMPurify (via `sanitizeHtml` configured securely) immediately prior to injection (`dangerouslySetInnerHTML` or `document.write`), creating a defense-in-depth layer that strips executable contexts regardless of how the string was constructed.
