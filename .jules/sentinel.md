## 2024-05-18 - Fix DOMPurify configuration for SVG and add XSS protection to generated SVGs
**Vulnerability:** XSS vulnerability was possible in DeedPlanGenerator and MutationPlanGenerator through unescaped SVG rendering using `dangerouslySetInnerHTML`. Furthermore, the previous DOMPurify configuration manually allowed specific tags and attributes which led to bugs rendering SVGs correctly by removing certain elements. `sanitizeHtml` was inappropriately applied to static SVG icons in `BeaconPicker`, causing React Hydration errors.
**Learning:** For SVGs, DOMPurify configuration should use `USE_PROFILES: { html: true, svg: true }` instead of manually specifying allowed tags and attributes to prevent functional regressions while ensuring strong security. Trusted static data (like static beacon symbols) doesn't need to be sanitized and doing so can cause SSR issues.
**Prevention:** Always use `sanitizeHtml` with DOMPurify on dynamically generated unescaped SVG strings before passing them to `dangerouslySetInnerHTML`. Never apply sanitization on hard-coded static enums. Ensure DOMPurify uses `USE_PROFILES: { html: true, svg: true }` for optimal SVG handling.
